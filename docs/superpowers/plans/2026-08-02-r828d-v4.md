**Goal:** CoreSDR drives the RTL-SDR Blog V4 (Rafael Micro R828D tuner) — spectrum, tune (including HF down to 500 kHz via the V4's built-in upconverter), gain — with the existing R820T2 path bit-for-bit unchanged.

**Architecture:** Parameterise the existing `R820T2` driver into an `R82xx` driver selected by a chip config (librtlsdr's own shape: one `tuner_r82xx.c` for both chips). The probe that today *rejects* an R828D instead *selects* it when the dongle is a Blog V4 (identified by USB string descriptors). V4-specific tune behaviour (a +28.8 MHz PLL offset below 28.8 MHz, notch/band-input register writes, one RTL2832U GPIO) rides inside `setFrequency`. New RTL2832U GPIO helpers also yield the bias tee.

**Tech Stack:** Swift 6 (strict concurrency), Swift Testing, `MockUSBTransport` golden-sequence tests. Reference sources: rtl-sdr-blog fork + osmocom commits `1261fbb285` / `138cd052f5` (archived in the feasibility session; facts restated inline below — tasks are self-contained).

**Spec:** `docs/2026-08-02-r828d-v4-feasibility.md` (the approved design).

## Global Constraints

- **The R820T2 path must not change behaviour.** Every existing test (golden vectors included) passes unmodified except where a task explicitly says it updates that test. Default config is `.r820t2`, so an unconfigured tuner behaves exactly as today.
- **Supported = R820T2, or R828D on a Blog V4.** A generic R828D stick (16 MHz tuner xtal, e.g. Astrometa) stays `SDRError.unsupportedTuner(detected: "R828D")` — the 16 MHz xtal path is explicitly out of scope.
- **V4 identification is an exact string match**: USB manufacturer `"RTLSDRBlog"` AND product `"Blog V4"` (the reference driver's `rtlsdr_check_dongle_model`; the V4 users guide tells users not to rewrite these EEPROM strings).
- **Mirror-the-reference discipline** (house style, see existing `R820T2.swift` doc comments): every ported routine's doc comment names its reference function (`r82xx_set_freq`, `rtlsdr_set_bias_tee_gpio`, …) and notes any deliberate divergence.
- **No hardware validation is possible in this plan** — no V4 is owned. All verification is mock-transport golden sequences. **Do not tag a release from this work**; merging to main is fine, but the version tag waits for real-V4 validation (tracked at the bottom).
- Public API changes are additive only (`SDRDeviceInfo` gains fields with defaulted init params; `SDRDevice.capabilities` keeps its signature).
- Swift 6 strict concurrency: shared mutable state lives in the existing `NSLock`-guarded holder classes (`TunerRegisterState`, `TuningState`); no new globals.
- Run tests with: `swift test` from the repo root.

```swift
/// Which Rafael Micro chip the driver is talking to. The raw value is the
/// human-readable name used in `SDRError.unsupportedTuner(detected:)`.
enum TunerModel: String, Sendable {
    case r820t2 = "R820T2"
    case r828d = "R828D"
}

/// Per-chip driver parameters, mirroring the `rafael_chip` switches in
/// `tuner_r82xx.c`. The two chips share the register map, init array, gain
/// tables, and 3.57 MHz IF; they differ in I2C address and `vco_power_ref`
/// — and the RTL-SDR Blog V4 (the only R828D dongle this driver supports)
/// additionally gets the V4 tune path (upconvert offset, notch, band
/// routing; Task 5). The V4's R828D runs from the RTL2832U's 28.8 MHz
/// clock, so no xtal parameter exists here — generic 16 MHz R828D sticks
/// are out of scope and remain unsupported.
struct R82xxConfig: Sendable, Equatable {
    let model: TunerModel
    let isBlogV4: Bool

    var i2cAddress: UInt16 { model == .r820t2 ? 0x34 : 0x74 }
    /// `vco_power_ref`: 2 for R820T, 1 for R828D. Drives the
    /// `vco_fine_tune` div_num nudge and the `nint` overflow bound.
    var vcoPowerRef: UInt8 { model == .r820t2 ? 2 : 1 }

    static let r820t2 = R82xxConfig(model: .r820t2, isBlogV4: false)
    static let blogV4 = R82xxConfig(model: .r828d, isBlogV4: true)
}
```

Replace `verifySupportedTuner()` in `R82xx.swift` (same probe mechanics, new decision):

```swift
/// Probes which Rafael Micro tuner answers on the I2C bus and returns the
/// config to drive it, or throws `SDRError.unsupportedTuner` for anything
/// this driver can't drive. Probe order and mechanics are unchanged from
/// the original verify-only version (0x34 first, then 0x74; chip ID 0x69
/// accepted in both bit orders; repeater re-disabled on every path).
///
/// An R828D is supported ONLY on an RTL-SDR Blog V4 (`isBlogV4`, decided
/// by the caller from USB string descriptors): the V4's R828D runs from
/// the RTL2832U's 28.8 MHz clock, whereas generic R828D sticks use a
/// 16 MHz tuner crystal this driver does not model — reported as
/// unsupported, exactly as before.
func detectTuner(isBlogV4: Bool) async throws -> R82xxConfig {
    try await setRepeater(enabled: true)
    let r820t2Present = await Self.probeChipID(rtl: rtl, address: Self.i2cAddress)
    let r828dPresent = r820t2Present
        ? false
        : await Self.probeChipID(rtl: rtl, address: Self.r828dI2CAddress)
    try await setRepeater(enabled: false)
    if r820t2Present { return .r820t2 }
    if r828dPresent && isBlogV4 { return .blogV4 }
    throw SDRError.unsupportedTuner(detected: r828dPresent ? "R828D" : nil)
}
```

Hand-derivation (checked against the reference math; the reviewer should re-derive):
tune 100 MHz, R828D/V4, xtal 28.8 MHz, stubbed `vco_fine_tune = 2`:
- LO = 100 MHz + 3.57 MHz = 103,570,000 Hz → freqKHz = 103,570
- mix_div search: 32 is the first divider with 103,570 × d in [1,770,000, 3,540,000) kHz → mix_div = 32, div_num = 4
- `vco_power_ref = 1` (R828D): fine-tune 2 > 1 → div_num 4 → **3** → reg 0x10 mask 0xe0 value **0x60** (an R820T2 with the same stub keeps div_num 4 / 0x80 — this write IS the observable chip difference)
- vco_freq = 103,570,000 × 32 = 3,314,240,000; vco_div = (28.8e6 + 65,536 × vco_freq) / 57.6e6 = 3,770,869
- nint = 57 → ni = 11, si = 0 → reg 0x14 = **0x0b**
- sdm = 35,317 = 0x89f5 → reg 0x16 = **0x89**, reg 0x15 = **0xf5**, and reg 0x12 mask 0x18 = 0x00 (sdm ≠ 0)

```swift
@Suite struct R828DPLLTests {
    @Test func tune100MHzUsesR828DPowerRef() async throws {
        let mock = MockUSBTransport()
        let rtl = RTL2832U(transport: mock)

        tuner.configure(.blogV4)
        mock.stubTunerPLLLocked(vcoFineTune: 2, address: 0x74)
        try await tuner.setFrequency(100_000_000)

        // Every write is [reg, value] at I2C address 0x74. Recorded in order.
        let writes = await mock.i2cWrites(address: 0x74)  // helper mirroring TunerProbeTests' accessor
        // div_num: R828D power-ref nudges 4 -> 3 (R820T2 golden vector keeps 0x8_ here).
        #expect(writes.contains(where: { $0.reg == 0x10 && ($0.value & 0xe0) == 0x60 }))
        // nint/sdm registers — the shared formula, unchanged by the chip.
        #expect(writes.last(where: { $0.reg == 0x14 })?.value == 0x0b)
        #expect(writes.last(where: { $0.reg == 0x16 })?.value == 0x89)
        #expect(writes.last(where: { $0.reg == 0x15 })?.value == 0xf5)
    }
}
```

```swift
// MARK: - GPIO

/// RTL2832U system-block GPIO registers (reference `GPO`/`GPOE`/`GPD`).
private static let gpoAddr: UInt16 = 0x3001
private static let gpoeAddr: UInt16 = 0x3003
private static let gpdAddr: UInt16 = 0x3004

/// Configures `gpio` as an output. Mirrors `rtlsdr_set_gpio_output`:
/// clear the pin's GPD (direction) bit, set its GPOE (output-enable) bit,
/// each as a read-modify-write of the 1-byte register.
private func setGPIOOutput(_ gpio: UInt8) async throws {
    let bit = UInt16(1) << gpio
    let gpd = try await readReg(.sys, Self.gpdAddr, length: 1)
    try await writeReg(.sys, Self.gpdAddr, gpd & ~bit, length: 1)
    let gpoe = try await readReg(.sys, Self.gpoeAddr, length: 1)
    try await writeReg(.sys, Self.gpoeAddr, gpoe | bit, length: 1)
}

/// Drives `gpio` high or low. Mirrors `rtlsdr_set_gpio_bit`.
private func setGPIOBit(_ gpio: UInt8, on: Bool) async throws {
    let bit = UInt16(1) << gpio
    let gpo = try await readReg(.sys, Self.gpoAddr, length: 1)
    try await writeReg(.sys, Self.gpoAddr, on ? gpo | bit : gpo & ~bit, length: 1)
}

/// Configures `gpio` as an output and drives it. Mirrors
/// `rtlsdr_set_bias_tee_gpio` (which despite the name is the generic
/// output-and-drive helper: GPIO 0 is the bias tee, GPIO 5 the V4's
/// upconverter power switch). GPIO writes are plain sys-block control
/// transfers — NOT I2C — so they are safe while the tuner's I2C repeater
/// is open (the V4 tune path calls this mid-sequence, as the reference
/// does).
func setBiasTeeGPIO(_ gpio: UInt8, on: Bool) async throws {
    try await setGPIOOutput(gpio)
    try await setGPIOBit(gpio, on: on)
}
```

```swift
func setFrequency(_ hz: UInt64, xtal: UInt32 = 28_800_000) async throws {
    var shadow = state.shadow
    var lastVcoCurr = state.lastVcoCurr
    defer {
        state.shadow = shadow
        state.lastVcoCurr = lastVcoCurr
    }

    let config = state.config
    // V4: automatic +28.8 MHz upconvert below 28.8 MHz (see v4UpconvertHz).
    let upconverted = (config.isBlogV4 && hz < Self.v4UpconvertHz)
        ? hz + Self.v4UpconvertHz : hz
    // r82xx_set_freq64: sideband 0, tuner_harmonic 0 -> LO is additive.
    let loFreq = upconverted + Self.intFreq // + if_band_center_freq (0)

    try await setRepeater(enabled: true)
    try await setMux(loFreq: loFreq, shadow: &shadow)
    try await setPLL(loFreq: loFreq, requestedHz: hz, xtal: xtal,
                     shadow: &shadow, lastVcoCurr: &lastVcoCurr)
    if config.isBlogV4 {
        try await setV4NotchAndRouting(requestedHz: hz, shadow: &shadow)
    }
    try await setRepeater(enabled: false)
}

/// Ports the V4 branch of `r82xx_set_freq` (post-PLL): notch filters and
/// three-way antenna-input routing, with the upconverter's GPIO-5 power
/// switch driven on band changes (a no-op on early V4 batches, which
/// ignore the pin). All decisions use the *requested* RF frequency, not
/// the upconverted LO. The GPIO write is a sys-block USB transfer, not
/// I2C, so issuing it inside the repeater bracket is safe (and matches
/// the reference, whose r82xx_set_freq runs entirely inside the
/// rtlsdr-layer repeater window).
private func setV4NotchAndRouting(requestedHz hz: UInt64, shadow: inout [UInt8]) async throws {
    // Notches OFF (0x00) inside the notch bands, ON (0x08) outside:
    // 0–2.2 MHz (AM), 85–112 MHz (broadcast FM), 172–242 MHz (DAB).
    let inNotchBand = hz <= 2_200_000
        || (hz >= 85_000_000 && hz <= 112_000_000)
        || (hz >= 172_000_000 && hz <= 242_000_000)
    try await writeRegisterMask(0x17, inNotchBand ? 0x00 : 0x08, mask: 0x08, shadow: &shadow)

    let band: V4Band = hz <= Self.v4UpconvertHz ? .hf
        : (hz < 250_000_000 ? .vhf : .uhf)
    guard band.rawValue != state.lastV4Band else { return }
    state.lastV4Band = band.rawValue

    // Cable 2 (HF input, behind the upconverter).
    let cable2: UInt8 = band == .hf ? 0x08 : 0x00
    try await writeRegisterMask(0x06, cable2, mask: 0x08, shadow: &shadow)
    // Power the upconverter only on HF (newer batches; GPIO 5).
    try await rtl.setBiasTeeGPIO(5, on: cable2 == 0)
    // Cable 1 (VHF input).
    try await writeRegisterMask(0x05, band == .vhf ? 0x40 : 0x00, mask: 0x40, shadow: &shadow)
    // Air in (UHF input; 0x00 = on).
    try await writeRegisterMask(0x05, band == .uhf ? 0x00 : 0x20, mask: 0x20, shadow: &shadow)
}
```
